# AGENTS.md — правила работы над Project S

## О проекте

Локальное десктоп-приложение для macOS: CRM + агентский харнес + AI-чат по проектам.
Полное ТЗ — в `SPEC.md` (при изменениях требований сначала правим ТЗ, потом прототип/код).

- `design/` — статический HTML/CSS/JS прототип UI на моках (для показа и согласования).
- Стек будущего приложения: Tauri 2 + Rust (свой агент-луп), React + TypeScript + Vite, **vanilla CSS — без Tailwind**.
- UI только на русском, светлая тема в стиле macOS (SF Pro, акцент #376A9F, тёмный тулбар #182533, сегментные контролы).

## Субагенты (обязательно)

- Нет-код и исследовательские задачи (поиск по кодовой базе, чтение больших файлов, разбор чужих папок, сравнение вариантов) — выносить в субагентов, а не жевать в основном контексте.
- **Одновременно — не более одного субагента.** Последовательно: один закончил → следующий.
- **Одна задача субагенту = один концерн.** Не давать огромные многосоставные задачи: дробить работу на атомарные срезы (например, отдельно «дерево файлов», отдельно «предпросмотр», отдельно «перетаскивание»). Крупная задача = несколько последовательных субагентов, каждый с узкой и проверяемой целью. Слишком широкая задача повышает риск провала и затрудняет проверку.
- **После каждого отработавшего субагента (одна фича/срез) — git-коммит.** Проверить сборку/тесты, затем закоммитить результат с осмысленным сообщением; только после этого запускать следующий срез. Не накапливать незакоммиченную работу.
- **Коммит делается целиком:** `git add -A && git commit …`. Не сверять пофайлово, какие файлы изменились, а какие нет, и не выбирать отдельные файлы — коммитим всё рабочее дерево. Так быстрее.
- Все промпты субагентам и их ответы — **на английском**. Пользователю результат всегда пересказывать **на русском**, кратко и по делу.
- В промпте субагента явно указывать: что сделать, что вернуть (формат), трогать или только читать.

## Скилл Ponytail

- Использовать скилл `ponytail` на нетривиальных кодовых задачах: минимальное полное решение, без оверинжиниринга и YAGNI-раздува.
- Не применять к мелочам (опечатки, одна строка, переименование) и там, где ТЗ прямо требует объёма.

## Безопасность данных (стрим!)

- Экраны приложения показываются в стриме. **Запрещено** класть куда угодно (моки, скриншоты, ТЗ, примеры) реальные данные: домены клиентов, ФИО, логины, пароли, FTP/IP, номера договоров, пути к рабочим папкам пользователя.
- Все примеры — вымышленные (`example.ru`, `ИП Петров`, IP из TEST-NET 192.0.2.0/24 и т.п.).
- Реальные директории пользователя (например `~/Documents/hdd_camouf_ru/WORK_FOLDER`) — **не трогать**: не читать вслух в моки, не переименовывать, не удалять. Только по явной просьбе.
- Перед показом/скриншотом — grep на реальные названия клиентов и доступы.

## Рабочий процесс

- Прототип `design/` проверять так: `python3 -m http.server 8731 --directory design` (file:// не работает в Playwright) → Playwright-снапшоты/скриншоты → скриншоты складывать в `design/preview/`, сервер после проверки останавливать.
- Любая фича: сначала пункт в `SPEC.md`, потом реализация в прототипе, потом проверка.
- После каждой завершённой фичи/среза субагента — коммит всего рабочего дерева (`git add -A`, см. раздел «Субагенты»). Не добавлять комментарии в код без запроса.
- Моки в прототипе — только захардкоженные данные в `app.js`; прототип не должен читать/писать диск.
- Релизные сборки ставим в `/Applications/Project-S.app`. После каждой сборки — `npm run app:install` (или `npm run app:update`, если сборка уже готова). Не класть приложение на Рабочий стол.

## Живые рабочие файлы (обязательно)

- `REFACTOR_PLAN.md` — **живая очередь срезов рефакторинга**, не архив. Выполненный срез **удаляется из файла полностью**: без `done`, зачёркиваний и пометок. Удаление — часть Definition of Done (код + зелёные тесты + коммит → абзац удалён, следующий шаг обновлён).
- `Q.md` — **живая очередь задач/багов** из тестирования приложения. Выполненный пункт **удаляется из файла полностью**: без «сделано/done», зачёркиваний и пометок.
- Оба файла **циклические**: после итерации пользовательского тестирования они снова наполняются новыми пунктами, агент проходит по ним и чистит выполненное. Так повторяется каждый цикл.
- В обоих файлах всегда лежит **только актуальный остаток**; история — в git. `BAG_REPORT.md` — сырые заметки пользователя, `Q.md` — оформленная очередь.

## Стиль кода

- Имена и UI-тексты — русские там, где видит пользователь; код/идентификаторы — английские.
- CSS — обычные классы, без фреймворков; держаться macOS-эстетики (см. `design/styles.css`).
- Изменения — маленькими шагами, каждая проверена.
