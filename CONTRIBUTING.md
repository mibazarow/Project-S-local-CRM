# Участие в Project-S

Спасибо за интерес к Project-S. Проект небольшой и развивается в одном основном репозитории. Перед крупной работой лучше сначала открыть обращение (issue) и согласовать направление.

## Лицензия и исходники

Project-S распространяется по модели **source-available**, а не как программа с открытым исходным кодом. Официальные сборки можно бесплатно использовать в любых целях, включая коммерческие. Модификация приложения и перепродажа/лицензирование приложения или его изменённых версий требуют предварительного письменного разрешения автора. Исходники открыты для просмотра в публичном репозитории; изменять, публиковать или распространять их без разрешения нельзя. Подробности — в [LICENSE.md](LICENSE.md).

Отправляя пул-реквест, патч, документацию или другой материал, вы подтверждаете, что имеете право его отправить, и предоставляете автору право использовать, изменять и распространять вклад в составе Project-S. Авторство Project-S (`Project-S by Михаил Базаров (bazarow.ru)`) должно сохраняться.

## Что можно предлагать

- баг-репорты с шагами воспроизведения;
- небольшие исправления и тесты;
- улучшения документации;
- платформенные исправления для macOS и Windows;
- идеи по UX и инструментам агента — сначала как обращение (issue).

Не присылайте реальные данные клиентов, ключи, токены, пароли, приватные IP и рабочие пути. Для примеров используйте вымышленные домены (`example.ru`), имена и адреса из TEST-NET.

## Локальная сборка

Нужны Node.js 20+, Rust stable и системные зависимости Tauri:

- macOS: Xcode Command Line Tools;
- Windows: Visual Studio Build Tools 2022 + Rust MSVC.

```bash
npm install
npm run tauri dev
```

Проверки перед PR:

```bash
npm test
npx tsc -b
npm run build
cd src-tauri && cargo test
./scripts/check.sh
```

`DOCS/` и `design/` не являются частью среды выполнения; изменения в них тоже приветствуются, если они не ломают существующие ссылки и превью.

## Стиль

- Интерфейс и пользовательские тексты — на русском; код и идентификаторы — на английском.
- CSS — обычные классы, без Tailwind и новых фреймворков.
- Не добавляйте комментарии без необходимости; следуйте стилю соседних файлов.
- Маленькие изменения проще проверять: один PR — один смысл.
- Не добавляйте секреты и реальные клиентские данные ни в код, ни в тесты, ни в скриншоты.

## Пул-реквест

1. Опишите проблему и решение.
2. Добавьте или обновите тесты, если меняется поведение.
3. Приложите скриншот для изменений интерфейса.
4. Убедитесь, что контроль качества пройден.
5. Не коммитьте `node_modules`, `target`, модели и локальные конфиги.
