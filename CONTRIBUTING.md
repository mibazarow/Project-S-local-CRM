# Contributing to Project-S

Спасибо за интерес к Project-S. Проект небольшой и развивается в одном основном репозитории. Перед крупной работой лучше сначала открыть issue и согласовать направление.

## Лицензия и доступ к исходникам

Project-S — **source-available**, не open source. Официальные сборки можно бесплатно использовать в личных и некоммерческих целях. Коммерческое использование — только с предварительного письменного разрешения автора. Исходники предоставляются по согласованию; публиковать или распространять их без разрешения нельзя. Подробности — в [LICENSE.md](LICENSE.md).

Отправляя pull request, патч, документацию или другой материал, вы подтверждаете, что имеете право его отправить, и предоставляете автору право использовать, изменять и распространять вклад в составе Project-S. Авторство Project-S (`Project-S by mibazarow`) должно сохраняться.

## Что можно предлагать

- баг-репорты с шагами воспроизведения;
- небольшие исправления и тесты;
- улучшения документации;
- платформенные исправления для macOS и Windows;
- идеи по UX и инструментам агента — сначала как issue.

Не присылайте реальные данные клиентов, ключи, токены, пароли, приватные IP и рабочие пути. Для примеров используйте вымышленные домены (`example.ru`), имена и адреса из TEST-NET.

## Локальная сборка

Нужны Node.js 20+, Rust stable и системные зависимости Tauri:

- macOS: Xcode Command Line Tools;
- Windows: Visual Studio Build Tools 2022 + Rust MSVC.

```bash
npm install
npm run tauri dev
```

Проверки перед PR:

```bash
npm test
npx tsc -b
npm run build
cd src-tauri && cargo test
./scripts/check.sh
```

`docs/` и `design/` не являются частью runtime; изменения в них тоже приветствуются, если они не ломают существующие ссылки и превью.

## Стиль

- UI и пользовательские тексты — на русском; код и идентификаторы — на английском.
- CSS — обычные классы, без Tailwind и новых фреймворков.
- Не добавляйте комментарии без необходимости; следуйте стилю соседних файлов.
- Маленькие изменения проще проверять: один PR — один смысл.
- Не добавляйте секреты и реальные клиентские данные ни в код, ни в тесты, ни в скриншоты.

## Pull request

1. Опишите проблему и решение.
2. Добавьте или обновите тесты, если меняется поведение.
3. Приложите скриншот для UI-изменений.
4. Убедитесь, что quality gate зелёный.
5. Не коммитьте `node_modules`, `target`, модели и локальные конфиги.

## Безопасность

Не открывайте публичный issue с эксплойтом. Пишите приватно владельцу репозитория в GitVerse: [@mibazarow](https://gitverse.ru/mibazarow). Подробности — в [SECURITY.md](SECURITY.md).

## Поведение

Участвуя в проекте, вы соглашаетесь соблюдать [CODE_OF_CONDUCT.md](CODE_OF_CONDUCT.md).
