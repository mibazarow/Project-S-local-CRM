7) **Расписания: результат должен приходить уведомлением macOS, клик — в чат; непрочитанное расписание «подмигивает».** Сейчас такое ощущение, что задачи по расписанию никуда не приходят: тишина, никакого оповещения.
   - По коду так и есть: уведомление отправляет только расписание вида `notify` (`scheduler/mod.rs`, `fire_due` → `notifier.notify`). Расписания `run_at` и `cron` молча запускают агента в сессии — никакого системного оповещения о результате нет, и кликать по нему нечего.
   - Нужно: когда задача по расписанию выполнилась — приходит стандартное уведомление macOS (Notification Center) с понятным заголовком (название расписания) и коротким текстом результата.
   - Клик по уведомлению: приложение выходит вперёд и открывает именно тот чат, где стоит это расписание, сразу с результатом выполнения (прокрутка к последнему ответу).
   - Непрочитанность: если уведомление закрыли/проигнорировали и в чат не зашли, плашка этого расписания в списке мягко «подмигивает» — лёгкая пульсация `box-shadow`, ненавязчивая, не раздражающая. Пульсация прекращается, как только расписание открыто (клик по плашке или по уведомлению).
   - Для этого нужно хранить признак прочтения (например `last_seen_at` / флаг «есть непрочитанный результат») и сбрасывать его при открытии чата расписания.
   - Ожидаемое поведение: ни одно сработавшее расписание не остаётся незамеченным — либо уведомление, либо визуальный маркер в списке; после прочтения маркер гаснет.
   - Развилка, которую стоит учесть при реализации: уведомлять в момент запуска задачи или после её завершения (логичнее после — тогда в уведомлении уже есть результат).

8) **Файл в чат нельзя перетащить из Finder — работает только скрепка.** Нужен drag & drop: тащу файл из Finder на окно чата (в Harness, в проекте, в «Заметках и файлах» — везде, где есть чат) и он прикрепляется к сообщению так же, как через скрепку.
   - По коду: в чат-компонентах нет обработчиков drop вообще (drag-и `onDrop`/`onDragOver` есть только внутри деревьев файлов/заметок и канбана — это внутренний drag, не файлы из ОС).
   - Важно: приложение на Tauri 2 и WKWebView, поэтому HTML5-события `drop` для файлов из Finder не приходят — нужны нативные события Tauri (`onDragDropEvent` из `@tauri-apps/api/webview`), опционально с проверкой флага `dragDropEnabled` в конфиге окна. То есть просто навесить `onDrop` на контейнер недостаточно.
   - Ожидаемое поведение: перетаскивание файла на область чата подсвечивает зону приёма, после отпускания файл(ы) появляются в списке вложений — как после выбора через скрепку; несколько файлов за раз поддерживаются.
   - Не файл и не папка (текст, ссылка) — просто игнорировать, без ошибок и мусора в вложениях.

15) **Переиндексация выглядит как «готово, но не готово»: «индексировано 0 из 101».** Запускаю переиндексацию из настроек — сразу приходит «Готово: индексировано 0 из 101 файлов». Ощущение, что поиск и индексация не работают вообще; надо перепроверить и поиск, и переиндексацию по проектам.
   - Причина сообщения (по коду): индексация инкрементальная. `index::index_root` считает в `IndexStats`: `files_seen` — все просмотренные, `files_indexed` — только те, что реально перезаписаны, `files_skipped` — неизменённые (совпали mtime/размер/хэш). В `components/settings/AgentTab.tsx` текст собирается как «индексировано ${filesIndexed} из ${filesSeen}», поэтому при неизменённых файлах всегда «0 из N». Это подтверждено тестом в `index/mod.rs` (второй проход: `files_indexed = 0`, `files_skipped = 3`).
   - Ожидаемое: формулировка честная и не пугающая — «Проверено 101 файл, обновлено 0, без изменений 101, удалено 0». Если индекс актуален, так и писать: «Индекс актуален», без «0 из 101».
   - Проверить сам поиск, а не только счётчики: (1) полнотекстовый поиск находит слово из свежего файла; (2) семантический — по смыслу, с включённым эмбеддером; (3) в режиме без эмбеддера вектора не пишутся — это должно быть явно видно в статусе, а не выглядеть как «поиск сломан»; (4) ошибки эмбеддинга сейчас складываются в `stats.errors`, а в итоговой строке показывается только их число — хорошо бы выводить первые ошибки.
   - Отдельно нужен полноценный «жёсткий пересбор» индекса (очистить `indexed_files`/`files_fts`/вектора для проекта и проиндексировать заново), потому что инкрементальный проход не лечит уже испорченный индекс, а сейчас такой кнопки нет.
   - Решение: отдельная кнопка «Пересобрать индекс полностью» с подтверждением; область — всё хранилище.
