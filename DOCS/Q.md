# Q.md — новая пачка доработок (из BAG_REPORT)

> **Правило ведения:** выполненную задачу **удаляем из этого файла полностью**. Никаких «сделано/done», зачёркиваний и пометок. В файле — только актуальный остаток. Закрыл пункт → удалил пункт.

2) **Управление настройками Project-S прямо из чата (пожелание).** Агент должен точно знать полный перечень своих настроек и уметь менять их из чата, не отправляя пользователя в UI настроек.
   - Пользователь просит словами («включи то», «поставь такое значение») — агент сам находит нужную настройку, показывает текущее значение, предлагает новое и применяет только после подтверждения.
   - Перед изменением — короткое понятное объяснение: что это за настройка, на что влияет, какие значения бывают, что изменится после правки.
   - Отдельный сценарий: пользователь не понимает смысл настройки — агент объясняет простыми словами, без жаргона, при необходимости с примером «как было / как станет».
   - Ручной путь через UI настроек остаётся полноценным и равноправным — чат лишь дополнительный способ.
   - Перечень настроек должен быть актуальным (агент видит реальные доступные ключи и их значения, а не догадывается), иначе изменение бессмысленно.

5) **Раздел «Проекты»: нужны две вкладки — «Текущие» и «Архивные» (новый функционал).** Сейчас список проектов один и понятия архива нет вообще (в коде нет ни флага, ни поля архивности).
   - Две вкладки внутри «Проектов»: «Текущие проекты» (то, что есть сейчас) и «Архивные проекты».
   - Любой проект можно переместить в архив и вернуть обратно в текущие; действие обратимое.
   - В архивном проекте нет раздела задач: задачи там не создаются и раздел не показывается. Остальное содержимое архивного проекта (файлы, заметки, данные, чаты и т.п.) работает точно так же, как в текущем.
   - Ожидаемое поведение: архив — это только статус видимости и отключение задач, данные и работоспособность проекта не меняются.

7) **Расширить набор инструментов управления компьютером (новый функционал).** Отдельная задача — выполняется в отдельной сессии другим агентом. Сейчас почти всё добирается через `bash`, но без типизированного результата, без подтверждений и с ручным парсингом вывода.

   Критичные пробелы, по приоритету:
   - **UI-автоматизация нативных приложений** (`applescript` / System Events): клик по координатам, хоткеи, пункты меню, ввод текста в активное окно. Инструмент `browser` управляет только Chrome через CDP, всё вне браузера (Finder, PhpStorm, 1Password, системные диалоги) — руками. Требует разрешения Accessibility.
   - **Буфер обмена с картинками** (`clipboard_get_image`): `clipboard_get` отдаёт только текст, поэтому сценарий «скопировал скриншот → разбери, что там» не работает без промежуточного сохранения в файл. Нужно: png/heic из буфера сразу в `ocr` или на анализ.
   - **Системный планировщик** (`launchd` / `launchctl`): создать, снять, посмотреть статус plist — чтобы задача выживала закрытие приложения. Текущие `schedule_*` работают только пока приложение открыто.
   - **Поиск по всему диску через Spotlight** (`mdfind`): по имени, типу, дате. `fs_list` и `fs_grep` ограничены указанной папкой и медленны на больших деревьях.
   - **Удаление в Корзину и восстановление** (`trash` / `restore`): `fs_delete` необратим, ошибка в одну команду стоит файлов.

   Дополнительно полезные:
   - `sysinfo` — CPU/RAM/диск/батарея/uptime/сеть одним JSON вместо парсинга `top`, `df`, `vm_stat`.
   - `notify` — локальные уведомления в Notification Center вне расписаний.
   - `open` — открыть файл, URL или приложение в дефолтном обработчике.
   - `archive` — zip/tar/7z с прогрессом: бэкапы проектов, распаковка релизов.
   - `fs_watch` — реакция на изменения файлов (fswatch): пересборка, синк, триггеры.
   - `keychain_get` — пароли доступа из Keychain через `security` вместо хранения в `datas.md`.
   - `window_list` / `window_focus` — список окон, фокус, тайлинг (сейчас есть только снимок по `windowId`).
   - `pdf_to_image` — рендер страниц PDF в png для превью и распознавания.
   - `defaults_write` — правка настроек macOS вместо сырого `defaults` в bash.

   Уже покрыто, отдельной обёртки не требует: `curl` (есть `http_request`), `tar`/`7z`, `ffmpeg`, `hdiutil`, `sips` (есть `image_transform`), `git`.

   Ожидаемое поведение:
   - Каждый новый инструмент возвращает типизированный результат (структурированный JSON), а не сырой текст под парсинг.
   - Опасные операции (удаление, запись вне рабочих папок, изменения системы) — только с подтверждением; обратимые — с откатом через `undo`.
   - Нехватка системных разрешений (Accessibility, Screen Recording, Full Disk Access) — явная ошибка с подсказкой, куда идти в настройках, а не молчаливый отказ или пустой результат.
