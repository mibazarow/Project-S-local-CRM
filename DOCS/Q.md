1) **Нет возможности закрепить чат в списке чатов Harness.** Нужна функция «закрепить чат» (pin).
   - В строке чата (при наведении/в контекстном меню) — иконка закрепления (канцелярская кнопка / pushpin).
   - Закреплённые чаты поднимаются в самый верх списка и идут друг под другом отдельной группой, выше незакреплённых.
   - Повторное нажатие снимает закрепление и возвращает чат в обычный порядок.
   - Состояние закрепления должно сохраняться между запусками приложения.
   - Визуал: у закреплённого чата иконка меняет цвет и наклоняется (эффект «воткнутой кнопки»), чтобы статус читался сразу; переход — с анимацией.

2) **При смене провайдера в селекторе моделей остаётся модель предыдущего провайдера.** Если добавлено несколько провайдеров, после выбора другого провайдера в списке моделей по-прежнему показана/выбрана модель от предыдущего — список моделей не перезагружается.
   - Ожидаемое поведение: при смене провайдера список моделей сразу перезагружается под выбранного провайдера (актуальный перечень, без «чужих» моделей).
   - Если у выбранного провайдера пользователь уже выбирал модель ранее — она подставляется автоматически (запоминаем последнюю выбранную модель отдельно для каждого провайдера). Если истории нет — берётся модель по умолчанию провайдера.

3) **Управление настройками Project-S прямо из чата (пожелание).** Агент должен точно знать полный перечень своих настроек и уметь менять их из чата, не отправляя пользователя в UI настроек.
   - Пользователь просит словами («включи то», «поставь такое значение») — агент сам находит нужную настройку, показывает текущее значение, предлагает новое и применяет только после подтверждения.
   - Перед изменением — короткое понятное объяснение: что это за настройка, на что влияет, какие значения бывают, что изменится после правки.
   - Отдельный сценарий: пользователь не понимает смысл настройки — агент объясняет простыми словами, без жаргона, при необходимости с примером «как было / как станет».
   - Ручной путь через UI настроек остаётся полноценным и равноправным — чат лишь дополнительный способ.
   - Перечень настроек должен быть актуальным (агент видит реальные доступные ключи и их значения, а не догадывается), иначе изменение бессмысленно.

4) **Кнопка «+» в панели расписаний должна вести в чат с готовым приветствием.** Иконку «+» («добавить расписание») оставляем как есть — она удобна. Меняется её поведение.
   - Клик по «+» открывает **новый чат в Harness**, создание расписания идёт словами в чате, а не в форме.
   - Агент сразу, без пустого экрана, приветствует пользователя и предлагает создать расписание: что нужно сделать, в какое время, разово или регулярно. Пример: «Помогу создать расписание. Что нужно делать, в какое время и как часто — разово или регулярно?»
   - Пользователь с первых слов понимает, что попал именно в создание расписания, а не в обычный чат.

5) **Создание задачи в проекте завершается ошибкой HTTP 400 «`reasoning_content` in the thinking mode must be passed back to the API».** Прошу создать задачу — задача реально создаётся, но в ответ приходит ошибка и подсказка «Проверьте Настройки → Модель». Текст:
   `Http error: HTTP 400: {"error":{"message":"The `reasoning_content` in the thinking mode must be passed back to the API. (request_id: 94a2e983-5ada-4c47-9499-0ff7821cd23b)","type":"invalid_request_error","param":null,"code":"invalid_request_error"}}`

Но она включается только при `requires_reasoning_passback`, а его считает эвристика `reasoning_passback_required()`: подстрока «deepseek» в `effective_base_url()` или в имени модели И включённый thinking (`reasoning_effort`). 6) **Раздел «Проекты»: нужны две вкладки — «Текущие» и «Архивные» (новый функционал).** Сейчас список проектов один и понятия архива нет вообще (в коде нет ни флага, ни поля архивности).

   - Вне наведения (без hover) кнопка не занимает места и не сдвигает текст, подсказка «скопировано» — как сейчас.

8) **Расширить набор инструментов управления компьютером (новый функционал).** Отдельная задача — выполняется в отдельной сессии другим агентом. Сейчас почти всё добирается через `bash`, но без типизированного результата, без подтверждений и с ручным парсингом вывода.

   Критичные пробелы, по приоритету:
   - **UI-автоматизация нативных приложений** (`applescript` / System Events): клик по координатам, хоткеи, пункты меню, ввод текста в активное окно. Инструмент `browser` управляет только Chrome через CDP, всё вне браузера (Finder, PhpStorm, 1Password, системные диалоги) — руками. Требует разрешения Accessibility.
   - **Буфер обмена с картинками** (`clipboard_get_image`): `clipboard_get` отдаёт только текст, поэтому сценарий «скопировал скриншот → разбери, что там» не работает без промежуточного сохранения в файл. Нужно: png/heic из буфера сразу в `ocr` или на анализ.
   - **Системный планировщик** (`launchd` / `launchctl`): создать, снять, посмотреть статус plist — чтобы задача выживала закрытие приложения. Текущие `schedule_*` работают только пока приложение открыто.
   - **Поиск по всему диску через Spotlight** (`mdfind`): по имени, типу, дате. `fs_list` и `fs_grep` ограничены указанной папкой и медленны на больших деревьях.
   - **Удаление в Корзину и восстановление** (`trash` / `restore`): `fs_delete` необратим, ошибка в одну команду стоит файлов.

   Дополнительно полезные:
   - `sysinfo` — CPU/RAM/диск/батарея/uptime/сеть одним JSON вместо парсинга `top`, `df`, `vm_stat`.
   - `notify` — локальные уведомления в Notification Center вне расписаний.
   - `open` — открыть файл, URL или приложение в дефолтном обработчике.
   - `archive` — zip/tar/7z с прогрессом: бэкапы проектов, распаковка релизов.
   - `fs_watch` — реакция на изменения файлов (fswatch): пересборка, синк, триггеры.
   - `keychain_get` — пароли доступа из Keychain через `security` вместо хранения в `datas.md`.
   - `window_list` / `window_focus` — список окон, фокус, тайлинг (сейчас есть только снимок по `windowId`).
   - `pdf_to_image` — рендер страниц PDF в png для превью и распознавания.
   - `defaults_write` — правка настроек macOS вместо сырого `defaults` в bash.

   Уже покрыто, отдельной обёртки не требует: `curl` (есть `http_request`), `tar`/`7z`, `ffmpeg`, `hdiutil`, `sips` (есть `image_transform`), `git`.

   Ожидаемое поведение:
   - Каждый новый инструмент возвращает типизированный результат (структурированный JSON), а не сырой текст под парсинг.
   - Опасные операции (удаление, запись вне рабочих папок, изменения системы) — только с подтверждением; обратимые — с откатом через `undo`.
   - Нехватка системных разрешений (Accessibility, Screen Recording, Full Disk Access) — явная ошибка с подсказкой, куда идти в настройках, а не молчаливый отказ или пустой результат.
