# Project S

Локальное десктопное приложение: **CRM + AI-агент + агентский харнес**. Один пользователь, всё работает на своей машине, без облака и серверной части. LLM подключается через любой OpenAI-совместимый API.

Коротко: папка проекта — это и есть проект. Внутри — файлы, задачи, доступы, заметки и чат с агентом, который видит контекст проекта. Отдельно есть «Харнес» — универсальный агент с доступом к компьютеру: файлы, терминал, браузер, SSH, планировщик, память и скиллы.

## Что умеет

- **Проекты/CRM** — список проектов, карточка клиента, файлы, доступы, импорт/экспорт, бэкапы.
- **Задачи** — канбан, приоритеты, дедлайны с временем, просрочка, таймер работы, чек-листы.
- **Файлы проекта** — дерево папок, список/плитка, предпросмотр, переименование, перемещение, drag-and-drop, импорт из Finder.
- **Заметки и файлы** — общий раздел для `.md` и любых файлов: изображения, PDF, текст, архивы; редактор заметок и превью.
- **AI-чат по проекту** — стриминг ответа, инструменты (задачи, файлы, поиск, интернет), подтверждения опасных действий, вложения.
- **Харнес** — сессии, расписания, память, скиллы, MCP-серверы, интернет, браузер, SSH, работа с процессами.
- **Поиск** — SQLite FTS5 + локальные эмбеддинги (ONNX Runtime, без Python).
- **Провайдеры LLM** — несколько профилей, активный выбирается в настройках; DeepSeek, Qwen и любые OpenAI-совместимые endpoint'ы.
- **Локальность** — данные, ключи и история лежат на машине пользователя; приложение не отправляет их в свой облачный сервис.

## Стек

| Слой | Технология |
|---|---|
| Оболочка | Tauri 2 |
| Бэкенд | Rust: агентный луп, SQLite, индексация, ONNX, CDP-браузер, планировщик |
| Фронтенд | React 19 + TypeScript + Vite |
| Стили | vanilla CSS, без Tailwind |
| БД | SQLite: метаданные, задачи, чаты, FTS5, векторный поиск |
| LLM | OpenAI-совместимый API (`/chat/completions` + tool calling) |

## Как устроено

```
React UI  ──Tauri IPC──  Rust core  ──  SQLite / файлы проекта
                              │
                              ├── агентный луп (tool calls → ответ)
                              ├── LLM-клиент (стриминг, провайдеры)
                              ├── поиск (FTS5 + эмбеддинги)
                              └── харнес (файлы, shell, браузер, SSH, MCP)
```

Рабочая директория по умолчанию — `~/Documents/PROJECT-S`:

```
PROJECT-S/
├── Projects/    # проекты; одна папка = один проект
├── Harness/     # рабочая территория харнеса
└── Settings/    # config, skills, .db, logs, backups
```

## Быстрый старт

Нужны macOS (v1), Node.js 20+, Rust stable и Xcode Command Line Tools.

```bash
npm install
npm run tauri dev     # приложение в dev-режиме
```

Проверки и сборка:

```bash
npm test              # фронтенд-тесты (vitest)
cargo test            # бэкенд-тесты (из src-tauri)
npm run build         # tsc + vite build
npm run app:build     # релизная сборка Tauri
npm run app:install   # сборка + установка в /Applications/Project-S.app
npm run app:update    # установить уже собранный бандл
```

## После клонирования: что не лежит в git

В репозитории **нет** `node_modules`, `src-tauri/target` и **модели эмбеддингов** (~330 МБ). Это нормально: они не должны раздувать git. `node_modules` и `target` восстановятся через `npm ci` и сборку.

### Модель эмбеддингов

В клоне `src-tauri/resources/models/embeddinggemma-2/` содержит только `.gitkeep`. Перед сборкой положите туда четыре файла:

- `model_quantized.onnx`
- `model_quantized.onnx_data`
- `tokenizer.json`
- `tokenizer_config.json`

Откуда взять:

- с Mac из демо-хранилища: `~/Documents/PROJECT-S/Settings/models/embeddinggemma-2/`;
- или скачать из Hugging Face `onnx-community/embeddinggemma-2-ONNX`: `onnx/model_quantized.onnx`, `onnx/model_quantized.onnx_data`, `tokenizer.json`, `tokenizer_config.json`.

Для `scripts/stage-embed-model.sh` можно задать `PROJECT_S_MODEL_SRC=/путь/к/embeddinggemma-2`; сам скрипт — bash/macOS. На Windows нативно он не запустится: нужен PowerShell-аналог или Git Bash/WSL.

Без модели приложение не падает, но семантический поиск деградирует до FTS; релизная сборка не упакует модель.

> **Для агента:** если после `git clone` нет `src-tauri/resources/models/embeddinggemma-2/model_quantized.onnx_data`, это ожидаемо — модель нужно доставить до сборки. Не удаляйте `.gitkeep`.

> **Windows:** порт ещё не реализован (см. `DOCS/WINDOWS-PORT.md`); одного клонирования недостаточно для сборки под Windows. Нужны платформенный слой, PowerShell-скрипты и WebView2-упаковка.

## Конфиг приложения: dev и release

Две копии приложения, одновременно они не запускаются: либо debug, либо release.

| Копия | Запуск | Хранилище |
|---|---|---|
| Демо/стрим | `npm run tauri dev` из репозитория | `~/Documents/PROJECT-S` |
| Личная | `/Applications/Project-S.app` | директория, выбранная в онбординге |

### Изоляция конфигов

Выбранная рабочая директория хранится в `working_dir.txt` в папке конфига приложения; у dev и release папки разные, чтобы онбординг одной не перезаписывал другую:

- debug: `~/Library/Application Support/app.project-s.ru/dev/working_dir.txt` — предзаполнен демо-путём.
- release: `~/Library/Application Support/app.project-s.ru/working_dir.txt` — путь, выбранный в онбординге.

Переменная окружения `PROJECT_S_CONFIG_DIR` задаёт папку конфига приложения явно.

При переходе на чистый онбординг старый release-маркер сохраняется как `working_dir.demo.bak`; это не активный конфиг.

### Онбординг release

- Выбирайте **новую пустую** директорию, а не `~/Documents/PROJECT-S` — иначе личная копия откроет демо-данные.
- У release свои `Settings/config` (LLM и провайдеры), их нужно настроить отдельно.

### Эмбеддинги

В **собранном** приложении модель `embeddinggemma-2` (~330 МБ) встроена и используется автоматически, если в рабочей директории нет локальной копии `Settings/models/embeddinggemma-2`. В git модели нет: после клонирования её нужно доставить до сборки (см. раздел «После клонирования» выше). Локальная копия в рабочей директории имеет приоритет — dev использует модель из демо-хранилища.

Релизные сборки готовят модель скриптом `scripts/stage-embed-model.sh`: источник по умолчанию `~/Documents/PROJECT-S/Settings/models/embeddinggemma-2`, переопределяется через `PROJECT_S_MODEL_SRC`. Скопированная папка `src-tauri/resources/models/` игнорируется git. Из-за модели приложение и DMG растут примерно на 330 МБ.

### Ежедневный цикл

1. Реальная работа — в release; баги и пожелания записываем.
2. Воспроизведение и фикс — в debug на демо-данных.
3. Проверка в debug → `npm run app:build` + `npm run app:update` → фикс уходит в release.
4. Демо-данные остаются вымышленными: реальные клиентские данные туда не попадают.

### Осторожно

- Не удаляйте `~/Documents/PROJECT-S`, пока демо-копия им пользуется.
- БД демо-копии лежит в `Settings/.db`; данные release — в выбранной им директории.

## Статус

- v1 реализована и работает на macOS.
- Windows 11 и Linux — **в планах**, не реализованы; оценки и подводные камни — в `DOCS/WINDOWS-PORT.md` и `DOCS/LINUX-PORT.md`.
- История разработки — в git.

## Безопасность данных

- Приложение локальное: реальные данные проектов не должны попадать в репозиторий, моки, скриншоты и документацию.
- Примеры в документации и тестах — вымышленные (`example.ru`, `ИП Петров`, TEST-NET 192.0.2.0/24).
- API-ключи хранятся в локальных конфигах приложения, не в репозитории.
