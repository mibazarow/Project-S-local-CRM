Разворачивает одну цель в веер изолированных агентов и сводит результат централизованно.
Оркестратор — main-сессия; дети — `Task`-субагенты (внутренние, невидимые) или Agent Manager
worktree-сессии (видимые, изолированные).

# Роли
- **Владелец (человек)** — ставит цель, аппрувит финальную интеграцию и мерж в main.
- **Оркестратор (main)** — декомпозирует, замораживает интерфейсы, раздаёт задачи, сортирует
  блокеры, собирает отчёты, интегрирует, держит гейты.
- **Ребёнок** — одна атомарная задача, изоляция по контексту. Архитектурных решений не
  принимает; спорное возвращает оркестратору.

# Жизненный цикл (каждый шаг с критерием «готово»)
1. **Декомпозиция** — цель → атомарные подзадачи, каждая = один концерн.
   Готово: список задач с явными критериями и без незакрытых зависимостей.
2. **Заморозка интерфейсов** — сигнатуры/контракты/точки соприкосновения фиксируем ДО старта.
   Готово: интерфейсы записаны; карта «файл → владелец» без пересечений.
3. **Веер** — раздать задачи детям (≤4 параллельно), по карточке задачи.
   Готово: у каждой задачи есть ветка/worktree, критерий «готово» и владелец.
4. **Сбор** — дети отдают единый формат; оркестратор интегрирует ветки по зависимостям.
   Готово: все отчёты получены; блокеры сняты или официально зафиксированы.
5. **Гейт** — build + тесты + линт + код-ревью на интегрированном состоянии.
   Готово: гейт зелёный. Красный → откат ветки, в main не мержим, задача назад ребёнку.
6. **Мерж** — только после гейта и аппрува владельца; основа ветки — актуальный main.
   Готово: main содержит мерж, гейт зелёный, ветка закрыта.

# Карточка задачи (оркестратор → ребёнок)
- Цель (один концерн) и критерий «готово».
- Замороженные интерфейсы, которые трогать нельзя.
- Разрешённые файлы (владение).
- Что вернуть (формат отчёта ниже).
- Зависимости (blocked-by).

# Отчёт ребёнка (единый формат)
1. Статус: done / blocked / partial.
2. Артефакты: ветка, файлы, коммиты, пути.
3. Блокеры (конкретно) — если есть.
4. Комментарии/риски для интеграции — без дизайн-решений.

# Владение и конфликты
- Один файл — один писатель в одной волне; пересечения только через замороженные интерфейсы.
- Конфликт мержа разрешает ребёнок в своей ветке ДО запроса на вливание.
- Один ресурс — один владелец: параллельные правки одного файла запрещены.

# Лимиты
- ≤4 агентов параллельно.
- Задача = один концерн, ~≤5 файлов; крупнее — дробить.
- Мелочь не выносим в worktree — делаем в main или обычным Task.

# Гейты, откат, безопасность
- Гейт обязателен перед мержем: build, тесты, линт, ревью. Нет аппрува — нет мержа.
- Провал гейта → `git reset --hard`/revert ветки; в main не мержим.
- Секреты только через env/secrets, не в коде.

# Координация
- Общая координация и блокеры — через board (`board_read`/`board_post`).
- Результаты работ — как итог `Task`; на доске не дублировать.
- Любое сообщение: итог, что сделано, блокеры, следующий шаг.
